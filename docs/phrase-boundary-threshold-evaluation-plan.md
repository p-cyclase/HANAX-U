# 句読点のフレーズ処理しきい値方式：実装・評価計画

> **対象：開発・検証向けの計画**
>
> この文書は、句読点の位置でフレーズ成分を評価し、フレーズ指令の追加と文境界のリセットを独立したしきい値で判定する方式の設計・評価計画である。実装前の暫定仕様を記録する。

## 目的

読点が多い長文でフレーズ成分が過剰に積み上がり、音高が高くなりすぎることを防ぐ。同時に、文中で十分に高さが保たれている場合は、句点の後も自然な流れを引き継げるようにする。

この方式では、句読点を一律に「指令を追加する」「必ずリセットする」と扱わない。境界時点のフレーズ成分に応じて、必要な場合だけ処理する。

## 判定対象

- 読点`、`と、VOICEVOXの`pauseMora`を正規化した`、`は、読点用しきい値によるフレーズ指令追加の対象とする。
- 句点・終端記号`。`、`！`、`？`は、句点用しきい値によるリセット判定の対象とする。
- 促音`っ`・`ッ`は通常モーラとして扱い、いずれの判定対象にも含めない。出力時だけRに置き換える。

## 共通する評価方法

句読点モーラの終了時点、すなわち句境界時点における**フレーズ成分だけ**を評価する。

1. その時点で有効なフレーズ指令からフレーズ成分を算出する。
2. 基底周波数Fbからの差を半音に換算する。
3. アクセント成分は判定に含めない。

句読点は240 ticksのモーラとして時間軸に含まれるため、評価時点は句読点の開始時点ではなく、当該モーラを通過した直後の境界時点とする。フレーズ指令を追加する場合も、この境界時点に置く。

## 句読点ごとの処理

| 境界 | 条件 | 処理 |
| --- | --- | --- |
| 読点`、`・`pauseMora` | フレーズ成分が読点用しきい値**以下** | 新しいフレーズ指令を通常の強さで追加する。 |
| 読点`、`・`pauseMora` | フレーズ成分が読点用しきい値より高い | 新しいフレーズ指令を追加せず、既存の状態を維持する。 |
| 句点`。`・`！`・`？` | フレーズ成分が句点用しきい値**以下** | それ以前のフレーズ指令とアクセント成分の状態を破棄し、後続モーラを語頭と同じ状態から計算する。 |
| 句点`。`・`！`・`？` | フレーズ成分が句点用しきい値より高い | 状態をリセットせず、フレーズ成分・アクセント成分を後続モーラへ引き継ぐ。 |

「リセット」は、基底周波数やRの生成規則を初期化する意味ではない。過去のフレーズ指令とアクセント成分を、後続モーラのF0計算に使わないようにする処理である。

## 設定項目の試作

比較実装では、詳細設定に次の2項目を置く。

| 項目 | 単位 | 意味 |
| --- | --- | --- |
| 読点でフレーズ指令を追加する下限 | 半音 | 読点の境界時点のフレーズ成分がこの値以下なら、新しいフレーズ指令を追加する。 |
| 句点でフレーズ状態をリセットする下限 | 半音 | 句点等の境界時点のフレーズ成分がこの値以下なら、フレーズ・アクセント状態をリセットする。 |

- どちらもFbからの相対値で扱う。基底周波数を変えても判定の意味が変わりにくい。
- 比較中の読点用の暫定初期値は`+2.5`半音である。
- 句点用の暫定初期値も`+2.5`半音とし、読点用とは独立して評価・決定する。
- 設定値と同じ場合は、いずれも「指令を追加する／リセットする」側として扱う。
- 最終的に採用する場合は、通常の設定保存・「変更を反映」・変換ログの対象に含める。

## 維持する仕様

- Rの数・位置・長さ・音高規則は、判定結果にかかわらず変更しない。
- 促音Rは促音自身を含む藤崎モデルの結果を使う。句読点のしきい値判定・リセットは行わない。
- 半音量子化、ポルタメント、VOICEVOXのアクセント正規化は変更しない。
- COEIROINKとVOICEVOXは、正規化後の共通モーラ列に対して同じ処理を使う。
- 文末の句読点に後続モーラがない場合、状態をリセットするかどうかは出力音高へ影響しない。ただし処理規則自体は同じとする。

## 評価計画

### 比較する値

読点用・句点用のしきい値を独立して評価する。

- 読点用：`+1`、`+2`、`+2.5`、`+3`、`+4`半音
- 句点用：`+1`、`+2`、`+2.5`、`+3`、`+4`半音

候補の間を確認する必要があれば、`0.5`半音刻みで追加比較する。比較対象には、しきい値方式を導入する直前の出力を用いる。旧方式をUIの選択肢として残す必要はない。

### 入力データ

- `test/normal_success.cink`
- `test/normal_success.vvproj`
- 読点の多い長文
- 読点の少ない短文
- 句点・感嘆符・疑問符を含む複数文
- 促音を含む文

公開できない実用データは`sample/`などGit管理対象外の場所に置く。

### ブラウザ・数値確認

- [ ] COEIROINKとVOICEVOXで正規化結果が同じ入力は、同じしきい値で半音量子化後のノート音高も一致する。
- [ ] 読点では、境界時点のフレーズ成分が読点用しきい値以下の場合だけ、フレーズ指令が追加される。
- [ ] 句点等では、境界時点のフレーズ成分が句点用しきい値以下の場合だけ、フレーズ成分・アクセント成分の状態がリセットされる。
- [ ] しきい値と同じ値の場合、読点では指令追加、句点ではリセットになる。
- [ ] 読点用・句点用の設定をそれぞれ変えると、対応する境界の音高処理だけが変わる。
- [ ] 読点が連続しても、音高が異常に上昇・下降しない。
- [ ] 促音Rの前後で、読点用の指令追加や句点用のリセットが誤って発生しない。
- [ ] Rの数・位置・長さ・規定の音高が、フレーズ処理以外の理由で変化しない。

### OpenUtau・聴感確認

- [ ] 各候補から出力したUSTXをOpenUtauで開ける。
- [ ] 読点の多い文で、高音へ不自然に張り付いたり、単調に下がり続けたりしない。
- [ ] 読点の少ない短文で、従来の抑揚から極端に離れない。
- [ ] 句点後を引き継ぐ場合とリセットする場合のどちらも、不自然な飛び方や停滞がない。
- [ ] 実用する音源・rendererで再生し、最終調声の叩き台として扱いやすい。

## 初期値の決定基準

読点用・句点用の初期値は、別々に次を満たす値を選ぶ。

1. 読点の多い文で、極端な高音が連続しない。
2. 文の切れ目が必要な箇所では、十分に新しい文として聞こえる。
3. 高い流れが続く箇所では、句点後も必要以上に機械的に切れない。
4. 基底周波数・BPMを変えても、判定の意味を説明できる。
5. 利用者に「句境界の高さが低いときだけ、持ち上げ直す／切り直す」と説明できる。

初期値を決めた後も、両方の詳細設定は残す。暫定である旨の表示を外し、音高仕様書・公開前テスト計画・更新履歴を最終仕様に合わせて更新する。
