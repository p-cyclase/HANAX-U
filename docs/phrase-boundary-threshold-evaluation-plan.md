# フレーズ境界しきい値方式：実装・評価記録

> **対象：開発・検証向けの記録**
>
> この文書は、COEIROINK・VOICEVOXから得られる`、`相当のフレーズ境界と疑問符`？`で、フレーズ成分を評価して「状態のリセット」と「フレーズ指令の追加」を判定する方式の設計・評価記録である。

## 背景

現行のCOEIROINK・VOICEVOXプロジェクトでは、入力した句点`。`と読点`、`は、モーラ列上では区別されず`、`相当の境界として扱われる。そのため、句点と読点の文字種を根拠に別々の音高処理を行うことはできない。

この方式では、境界の文字種ではなく、境界時点に残っているフレーズ成分の高さだけを根拠に、必要な処理を決める。

## 判定対象

- COEIROINKの`、`モーラ、およびVOICEVOXの`pauseMora`を正規化した`、`を対象とする。
- VOICEVOXの`isInterrogative`から正規化した`？`は、終端境界としてこのしきい値判定の対象に含める。休符Rの高さには、既存の疑問符用規則を使う。
- 促音`っ`・`ッ`は通常モーラとして扱い、境界判定の対象には含めない。出力時だけRに置き換える。

## 共通する評価方法

各フレーズ境界の終了時点における**フレーズ成分だけ**を評価する。

1. その時点で有効なフレーズ指令からフレーズ成分を算出する。
2. 基底周波数Fbからの差を半音に換算する。
3. アクセント成分は判定に含めない。

`、`と`？`は240 ticksのモーラとして時間軸に含まれるため、評価時点は各モーラの開始時点ではなく、当該モーラを通過した直後の境界時点とする。フレーズ指令を追加する場合も、この境界時点に置く。

## 境界ごとの処理

各`、`相当境界および`？`の境界で、同じフレーズ成分を使って、次の順に判定する。

1. **状態をリセットするか**を判定する。フレーズ成分が「フレーズ成分リセット閾値」以下なら、それ以前のフレーズ指令とアクセント成分の状態を破棄し、語頭と同じ新しいフレーズ指令を置く。
2. **リセットしなかった場合だけ**、新しいフレーズ指令を置くかを判定する。フレーズ成分が「フレーズ指令追加閾値」以下なら、状態を引き継いだまま境界時点に通常の強さのフレーズ指令を置く。

「リセット」は、基底周波数やRの生成規則を初期化する意味ではない。過去のフレーズ指令とアクセント成分を、後続モーラのF0計算に使わないようにする処理である。

### 3段階の状態

フレーズ成分リセット閾値をフレーズ指令追加閾値以下にすることで、境界は次の3段階になる。この順序は推奨であり、必須ではない。

| 境界時点のフレーズ成分 | 処理 |
| --- | --- |
| フレーズ成分リセット閾値以下 | 状態をリセットし、新しいフレーズ指令を置く。 |
| フレーズ成分リセット閾値より高く、フレーズ指令追加閾値以下 | 状態を引き継ぎ、新しいフレーズ指令を置く。 |
| フレーズ指令追加閾値より高い | 状態を引き継ぎ、フレーズ指令は追加しない。 |

フレーズ成分リセット閾値がフレーズ指令追加閾値を超える場合は、リセットが優先される。このとき「状態を引き継いで指令を追加する」中間段階は生じず、「リセット＋指令追加」と「引き継ぎのみ」の2段階になる。

## 設定項目と初期値

詳細設定に次の2項目を置く。

| 項目 | 初期値 | 単位 | 意味 |
| --- | --- | --- |
| フレーズ成分リセット閾値 | `+1.5` | 半音 | 境界時点のフレーズ成分がこの値以下なら、フレーズ・アクセント状態をリセットする。 |
| フレーズ指令追加閾値 | `+2.5` | 半音 | 境界時点のフレーズ成分がこの値以下なら、新しいフレーズ指令を置く。 |

- 両方ともFbからの相対値で扱う。基底周波数を変えても判定の意味が変わりにくい。
- `test/normal_success.cink`／`.vvproj`を用いた自動走査で、3段階の状態をすべて確認でき、CINK・VVProjの出力一致も維持できる値として決定した。
- 設定値がしきい値と同じ場合は、リセット・指令追加を行う側として扱う。
- 最終的に採用する場合は、通常の設定保存・「変更を反映」・変換ログの対象に含める。

## 維持する仕様

- Rの数・位置・長さ・音高規則は、境界判定の結果にかかわらず変更しない。
- 促音Rは促音自身を含む藤崎モデルの結果を使う。フレーズ境界の判定・リセットは行わない。
- 半音量子化、ポルタメント、VOICEVOXのアクセント正規化は変更しない。
- COEIROINKとVOICEVOXは、正規化後の共通モーラ列に対して同じ処理を使う。

## 評価記録

### 使用するテストデータ

- `test/normal_success.cink`
- `test/normal_success.vvproj`

この2ファイルには複数の`、`相当境界と促音が含まれ、正規化後のモーラ列・アクセント情報が対応する。新しいテストデータを追加せず、同一入力に対して2つのしきい値を変え、3段階の挙動を比較する。

### 比較する値

| 比較目的 | フレーズ成分リセット閾値 | フレーズ指令追加閾値 |
| --- | ---: | ---: |
| 低い境界での立て直し | `+1.5` | `+2.5` |
| 常に状態を引き継ぐ側の極端値 | `0` | `0` |
| 常に立て直す側の極端値 | `+12` | `+12` |
| 中間帯の広さを確認 | `+1` | `+3` |

必要なら、候補の間を`0.5`半音刻みで追加比較する。

### ブラウザ・数値確認

- [ ] COEIROINKとVOICEVOXで正規化結果が同じ入力は、同じしきい値で半音量子化後のノート音高も一致する。
- [ ] フレーズ成分リセット閾値以下では、過去のフレーズ指令とアクセント成分を使わず、新しいフレーズ指令が置かれる。
- [ ] フレーズ成分リセット閾値より高く、フレーズ指令追加閾値以下では、状態を引き継いだまま新しいフレーズ指令が置かれる。
- [ ] フレーズ指令追加閾値より高い場合は、状態を引き継ぎ、新しいフレーズ指令を置かない。
- [ ] しきい値と同じ値の場合は、リセット・指令追加を行う。
- [ ] フレーズ成分リセット閾値をフレーズ指令追加閾値より高くした場合も、リセット時には語頭と同じフレーズ指令が置かれ、2段階の処理として継続できる。
- [ ] 促音`っ`・`ッ`の前後で、境界判定・リセットが誤って発生しない。
- [ ] Rの数・位置・長さ・規定の音高が、フレーズ処理以外の理由で変化しない。

### OpenUtau・聴感確認

- [ ] 各候補から出力したUSTXをOpenUtauで開ける。
- [ ] 読点の多い文で、高音へ不自然に張り付いたり、単調に下がり続けたりしない。
- [ ] 低い境界では、新しいフレーズとして不自然なく立て直される。
- [ ] 中間帯では、既存の流れを保ちながら抑揚を追加できる。
- [ ] 高い境界では、必要以上にフレーズ指令を重ねない。
- [ ] 実用する音源・rendererで再生し、最終調声の叩き台として扱いやすい。

## 初期値の採用理由

フレーズ成分リセット閾値`+1.5`半音、フレーズ指令追加閾値`+2.5`半音を採用した。

`test/normal_success.cink`／`.vvproj`では、7個の境界について「リセット＋追加」が3件、「追加のみ」が1件、「引き継ぎのみ」が3件となり、3段階の状態をすべて確認できた。CINK・VVProjのノート列は一致し、従来方式との差も半音量子化後の発声音高では生じなかった。

この初期値は、低くなった流れを立て直しつつ、中程度の高さでは抑揚を追加し、高い流れでは不要なフレーズ指令を重ねないための基準である。3段階の変化を使う場合は、`フレーズ成分リセット閾値 ≤ フレーズ指令追加閾値`を推奨する。詳細設定からは、逆順を含めて変更できる。

初期値を決めた後も、両方の詳細設定は残す。実用テストで新たな課題が見つかった場合は、この記録と音高仕様書・公開前テスト計画を更新する。
