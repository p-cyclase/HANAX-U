# 通常変換テストデータ仕様

## 目的

COEIROINK・VOICEVOXの通常変換について、Importer、Generator、Exporter、WebUIの基本動作を継続して確認できる決定稿テストプロジェクトを定める。

この文書は、`test/`へ追加する入力プロジェクトと、その受け入れ条件を定義する。実用目的の`sample/`とは分け、GitHubで公開できる内容だけを採用する。

## 共通方針

- 台詞はオリジナル文、または公開・再配布に問題のない文章を使用する。各フィクスチャの台詞出典と採用根拠は、[`test/README.md`](../test/README.md)に記録する。
- 絶対パス、ユーザー名、メールアドレス、個人を特定し得る情報を含めない。
- 話者名・スタイル名を含む形式では、権利者または管理者が公開を許可した名称だけを使用する。COEIROINK正常系では、管理者が扱う音源名`蛸之風みもり`を使用する。
- 実在する音源やエンジンに紐づくUUIDは公開しない。テストデータでは話者ID・エンジンIDを架空UUIDへ置き換え、同じ話者・別スタイルの関係だけを保持する。
- テストデータは、特定のUTAU音源・rendererがなくてもブラウザ上の入力、プレビュー、USTX・ZIP出力を確認できるものとする。
- 音源の実際の再生確認は環境依存の確認として、公開前テスト計画で別に扱う。
- 音高生成は設定値の見直しにより意図して変わる可能性があるため、USTX全文を固定したゴールデンファイルにはしない。代わりに、入力から得るべき構造、プレビュー、ZIP構成、命名、ログの受け入れ条件を確認する。

## 制定する入力プロジェクト

### `normal_success.cink`

COEIROINKの通常変換正常系。少なくとも次を含める。

- 複数のセリフ行またはアクセント句
- アクセントあり・なしが区別できるモーラ
- 読点相当の休止、促音、`ん`を含むセリフ
- 公開・再配布に問題のない台詞
- 話者情報を取得できる構造

`speakerName`には`蛸之風みもり`を使用する。`styleName`は`のーまる`と`ささやき`、`styleId`は`0`と`1`を使用する。`speakerUuid`と`engineUuid`は架空UUIDへ置き換える。ほかの実在音源名・キャラクター名は、公開テストデータへ追加しない。

期待結果は、入力、プレビュー、USTX単体、TXT ZIP、LAB ZIPが正常に出力されること。音高は半音単位であり、休符`R`を含むことを確認する。

### `normal_success.vvproj`

VOICEVOXの通常変換正常系。少なくとも次を含める。

- 複数のセリフ行またはアクセント句
- アクセント位置が異なる句
- `pauseMora`相当の休止、促音、`ん`を含むセリフ
- カタカナを含み、ひらがな変換を確認できるモーラ
- 異なる`styleId`を持つ話者・スタイル情報

`speakerId`と`engineId`は架空UUIDへ置き換え、`styleId`は`0`と`1`を使用する。期待結果は、入力、プレビュー、USTX単体、TXT ZIP、LAB ZIPが正常に出力されること。話者は内部IDとして表示され、話者マッピングの候補として区別されることを確認する。

## 出力設定の確認

上記の正常系テストデータを用い、次を確認する。

- 3種類のファイル名形式が、USTXトラック名、TXT、LABのファイル名へ反映される。
- LABのオン・オフで、TXTとUSTXを維持したままLABの有無だけが変わる。
- フラグ設定がUSTXのプロジェクト規定値へ反映される。
- 話者マッピングの`singer`、`phonemizer`、`renderer`がUSTXへ反映される。
- 出力設定の変更だけでは、プレビューの音高計算を再実行しない。

## 入力エラーの確認

壊れたプロジェクトや空ファイルは、公開リポジトリに置く必要がある場合だけ、次の名前で最小限に作成する。

- `normal_invalid.cink`
- `normal_invalid.vvproj`
- `normal_invalid_zip.cink`
- `normal_empty.cink`

`normal_invalid.cink`と`normal_invalid.vvproj`の内容は`{`の1文字だけとし、拡張子が正しいJSON構文エラーを確認する。`normal_invalid_zip.cink`は先頭の`PK`だけを含む2バイトとし、壊れたZIP入力のエラーを確認する。`normal_empty.cink`は0バイトとし、空ファイル専用のエラーを確認する。

サイズ上限の確認に使う大容量ファイルは、リポジトリを不要に大きくしないためGit管理しない。ローカルで作成したデータを使い、公開前テスト計画に従って確認する。

## 追加時の確認

決定稿を`test/`へ追加する前に、次を確認する。

- HANAX-UのImporterが読み込める入力ファイルである。話者名・スタイル名は、公開を許可したものだけを含め、話者ID・エンジンIDは架空UUIDを使う。
- 本文・話者情報・メタデータに公開したくない情報が含まれない。
- `.cink`・`.vvproj`の実際の構造を保ち、手作業で単純化しすぎていない。
- この文書と`test/README.md`に、各ファイルの目的と期待結果を追記する。
- [公開前テスト計画](pre-release-test-plan.md)の該当項目で利用できる。
