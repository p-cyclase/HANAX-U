# 読点のフレーズ指令しきい値方式：実装・評価計画

> **対象：開発・検証向けの計画**
>
> この文書は、読点でのフレーズ指令追加をしきい値で判定する方式を比較実装し、HANAX-Uの公開仕様として採用する初期値を決めるための計画である。比較実装の内容は[音高生成アルゴリズム](pitch-generation-algorithm.md)にも暫定仕様として記録する。

## 目的

読点が多い長文でフレーズ成分が過剰に積み上がり、音高が高くなりすぎることを防ぐ。同時に、読点ごとの音高変化を失わせず、現行方式から大きくかけ離れない自然な叩き台を作る。

## 現行方式

現行の通常変換では、読点`、`およびVOICEVOXの`pauseMora`の位置で、過去のフレーズ成分を上限付きで持ち越し、新しいフレーズ指令を加える。

この方式は抑揚を保てる一方、文中の読点が多い場合に、文脈によってはフレーズ成分が高い側へ寄りやすい。

## 比較実装する方式

### 判定対象

- 通常の読点`、`と、VOICEVOXの`pauseMora`を正規化した`、`だけを対象とする。
- 句点`。`、感嘆符`！`、疑問符`？`は対象外とする。これらは従来どおり、後続モーラを文頭と同じ状態から計算する完全リセットである。
- 促音`っ`・`ッ`は対象外とする。出力時にはRとなるが、句境界やフレーズ指令判定には使わない。

### 判定手順

読点の直後に続く最初の発声モーラの中央時点について、**アクセント成分を除いたフレーズ成分のみ**を評価する。

1. 既存のフレーズ指令だけで、当該時点の予測F0を算出する。
2. 基底周波数Fbとの差を半音へ換算する。
3. その値が「フレーズ指令を追加する下限」を**下回る**場合だけ、新しいフレーズ指令を通常の強さで追加する。
4. 下限以上なら、新しいフレーズ指令は追加しない。

アクセント成分を判定に含めない。アクセントの谷や山に左右されず、文全体の基準的な高さだけを基準にするためである。

## 設定項目の試作

比較実装では、詳細設定に次の数値入力を一時的に追加する。

| 項目 | 単位 | 意味 |
| --- | --- | --- |
| 読点でフレーズ指令を追加する下限 | 半音 | 読点後の予測基準音高が、基底周波数からこの値未満の場合にだけ指令を追加する。 |

- 設定値は、基底周波数からの相対値で扱う。話者ごとにFbを変えても、判定の意味が変わりにくい。
- 評価中の暫定初期値は`+2.5`半音とする。公開時の初期値は、下記の評価を経て決定する。
- 最終的に採用する場合は、通常の設定保存・「変更を反映」の対象に含める。

## 実装上の確認事項

- 読点後に発声モーラがない文末読点では、後続モーラがないため追加判定を行わない。
- 判定時点と、実際に追加するフレーズ指令の時刻を混同しない。判定は「読点後の最初の発声モーラ中央」、指令は従来どおり読点境界に置く。
- 既存のRの数・位置・長さ・音高規則、アクセント成分、半音量子化、ポルタメントは変更しない。
- COEIROINKとVOICEVOXは、正規化後の共通モーラ列に対して同じ処理を使う。

## 評価計画

### 比較する値

暫定的に、下限を`+1`、`+2`、`+3`、`+4`半音として同じ入力を変換する。必要なら、候補の間を`0.5`半音刻みで追加比較する。

比較対象には、しきい値方式を導入する直前の実装による出力を用いる。旧方式は比較専用のUI選択肢として残さない。完全リセット方式は採用候補ではないが、下限`+0`に近い極端な挙動を考える際の参考とする。

### 入力データ

- `test/normal_success.cink`
- `test/normal_success.vvproj`
- 実用上の確認用として、読点の多い長文、読点の少ない短文、句点を含む複数文を各1件以上用意する。権利上公開できない実用データは`sample/`などGit管理対象外の場所に置く。

### ブラウザ・数値確認

- [ ] 各しきい値で、COEIROINKとVOICEVOXの正規化結果が同一なら、半音量子化後のノート音高も一致する。
- [ ] 読点後の予測フレーズ成分が下限未満の場合だけ、フレーズ指令が追加される。
- [ ] 下限以上の場合、新しいフレーズ指令が追加されない。
- [ ] 読点が連続しても、音高が異常に上昇・下降しない。
- [ ] 句点・感嘆符・疑問符の後は、しきい値にかかわらず完全リセットになる。
- [ ] 促音Rの前後で、読点用の判定や完全リセットが誤って発生しない。
- [ ] Rの数・位置・長さ・規定の音高が、フレーズ指令処理以外の理由で変化しない。

### OpenUtau・聴感確認

- [ ] 各候補から出力したUSTXをOpenUtauで開ける。
- [ ] 読点の多い文で、高音へ不自然に張り付いたり、単調に下がり続けたりしない。
- [ ] 読点の少ない短文で、現行方式と極端に異なる印象にならない。
- [ ] 句点後が新しい文として自然に始まる。
- [ ] 実用する音源・rendererで再生し、最終調声の叩き台として扱いやすい。

## 初期値の決定基準

次の条件を最もバランスよく満たす値を、公開版の初期値とする。

1. 読点の多い文で、極端な高音が連続しない。
2. 読点の少ない文で、現行方式の抑揚から大きく離れない。
3. 基底周波数・BPMを変えても、判定の意味を説明できる。
4. 利用者に「読点後がこの高さより低ければ持ち上げる」と簡潔に説明できる。

初期値を決めた後も、しきい値の詳細設定は残す。暫定である旨の表示を外し、旧方式に関する比較用の記述だけをUI・保存設定・ログから削除する。音高仕様書と公開前テスト計画も、最終仕様に合わせて更新する。
